# `avatar`

- Character Data: the `*.character.json` description (format 2; format 1 migrates in `migrate.rs`), base and item manifests (`*.base.json`, `*.item.json`), the catalogue, material values per shading model, checks (`Problem`), and `resolve` (description + `Library` to `Resolved`, activating live `Shrink_Under` when worn under a higher-layer garment). `fit/` (ADR-0035/0041/0045/0046): non-destructive garment fitting over immutable canonical rest geometry using `proxy.rs` (`FitProxy`/`SkirtProxy` + Layer Envelopes 0–3), `bind.rs` (part-restricted confident proxy binding), `inpaint.rs` (`faer` sparse Cholesky biharmonic skin-weight and frame-relative morph-delta inpainting), `validate.rs` (read-only manifold & chord-sag gate), `cover.rs` (1024² UV cover map), and `import_garment` (`HomeFrame`, no cross-frame rest warping); geometry in file space (metres), so the crate builds at opt-level 3 in dev.
- Every schema, rule and version is in `docs/development/character-studio/architecture.md`; change it there first. Only the lead changes a contract (plan sections 5 and 11.7).
- Depends on `assets` only (and may on `core`; `anim` is a dev-dependency, for posing as the runtime does in tests): no rendering, UI, Instances or editor state, so `player`, `server` and `editor` can all use it. `resolve` makes no Instances and loads no models.
- A new optional field needs no version bump: a description keeps unknown fields at its top level and on worn items; manifests and the catalogue ignore them. A new value in an existing enum breaks older engines; a changed meaning bumps `format_version` with a migration. Never panic on a bad file.
- Tests: unit tests per module; `tests/shipped_library.rs` checks `assets/characters/` (presets included) against its models. After changing a package's scripts run its `manifests.py` (the realistic one needs numpy) and `presets.py`, then `python -I assets/characters/catalogue.py`.
