# `avatar`

- Character Data: the `*.character.json` description (format 2; format 1 migrates in `migrate.rs`), base and item manifests (`*.base.json`, `*.item.json`), the catalogue, material values per shading model, the checks (`Problem`) and `resolve` (a description and a `Library` to `Resolved`, the plain data `gameplay`'s applier uses; one identity layer per parameter, corner and region mask). R1 (ADR-0040): parameter metadata, features and handles, item capabilities, presets (`*.preset.json`, descriptions with a `preset` block; `preset.rs`, `apply_preset`) and `randomize.rs`. Content states (ADR-0043): an item's `quality`, `production`/`legacy`/`draft`, unset is legacy (`content_state.rs`: `check_declared_state` for shipped items, `production_slots`); Randomize draws production only. R5 (ADR-0042): makeup and markings, the description's `skin` block and the manifest's `skin_layers` (`skin.rs`), resolved to `layer_<id>_<field>` material values. `LIBRARY_FOLDER` is the library's folder in a project. `fit/` (CO9, ADR-0035/0041): binding a garment to a body, transferring the body's weights and identity and corrective shapes, push-out from the body and lower layers, the posed fit (`pose.rs`, `posed.rs`: correctives made to follow the binding in poses), coverage, the import flow (`import_garment`, `examples/import_garment.rs`); geometry in file space (metres), so the crate builds at opt-level 3 in dev.
- `provenance.rs` (wave 5, decision 11): an imported item's `*.provenance.json`, the licence rule (`licence_terms`), `check_provenance` and a game's `character_credits`; `fit::import_garment_with` keeps an intake's placement. The intake scripts are `assets/characters/realistic/import/`.
- Every schema, rule and version is in `docs/development/character-studio/architecture.md`; change it there first. Only the lead changes a contract (plan sections 5 and 11.7).
- Depends on `assets` only (and may on `core`; `anim` is a dev-dependency, for posing as the runtime does in tests): no rendering, UI, Instances or editor state, so `player`, `server` and `editor` can all use it. `resolve` makes no Instances and loads no models.
- A new optional field needs no version bump: a description keeps unknown fields at its top level and on worn items; manifests and the catalogue ignore them. A new value in an existing enum breaks older engines; a changed meaning bumps `format_version` with a migration. Never panic on a bad file.
- Tests: unit tests per module; `tests/shipped_library.rs` checks `assets/characters/` (presets included) against its models. After changing a package's scripts run its `manifests.py` (the realistic one needs numpy) and `presets.py`, then `python -I assets/characters/catalogue.py`.
