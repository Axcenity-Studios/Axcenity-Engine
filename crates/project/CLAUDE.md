# `project`

- Loads and saves project folders, including CSS source files. Open one file from the map in `docs/project-and-export.md`.
- `lib.rs` is the manifest, load and save; `scripts.rs`, `stylesheets.rs` and `templates.rs` hold those (re-exported from `lib.rs`). `build.rs` embeds the repository's `templates/` (the genre templates, `docs/project/templates.md`). `ui_graphs.rs` compiles `ui/*.uigraph.json` to LocalScripts under their ScreenGuis. `world_file.rs` is `world.json`; `levels.rs` the other levels, `levels/<name>.world.json` (Workspace only; `load_with_level`, `save_level`, `set_start_level`; `docs/project/levels.md`); `strings.rs` the string table, `strings.json`. `migrate.rs` upgrades an older manifest, keeps the previous files and puts them back if the upgraded world doesn't read (`migrate_animation.rs` is the 2 → 3 step: one clip format, state machines; `migrate_shapes.rs` the 5 → 6 step and the only reader of old clip and block-condition shapes); `compat.rs` says how a folder would open, without writing, so the editor can ask before upgrading. `terrain_files.rs` is Terrains' data folders (codecs in `terrain::files`). `packed.rs` packs a game; `branding.rs` is the manifest's icon and banner and their checks (headers only, `docs/project/export.md`); `package.rs` is asset packages (`.axpkg`, `docs/project/packages.md`). `versions.rs` keeps save history (pins, checkpoints, restores); `versions/changes.rs` is its change view (Instance diff by path, line diff); `backup.rs` is Back Up Project (`docs/project/export.md`). `validate.rs` is the editor's asset check (`check_assets`); it must not write the project. `asset_fix.rs` plans its fixes (`plan_fix`) without writing; only the ignored list (`.axcenity/asset-check.json`) is written there. `asset_refs.rs` finds every reference to an asset, the unused ones, and plans a rename (`find_references`, `unused_assets`, `plan_rename`), also without writing. `object_scripts.rs` loads scripts inside objects (`SourceFile`) and merges the start order (`docs/project/world.md`). `prefabs.rs` reads prefab files and keeps placed copies, nested prefabs and variants up to date (`Prefabs::refresh`, run by every load; format in `docs/project/world.md`). `world_presets.rs` is world presets (`.axworld`, PW3, `docs/terrain.md`). `character_library.rs` is a project's character library (Character Studio overhaul CO3, `docs/development/character-studio/architecture.md` section 15). No library is built into the engine (ADR-0050): the packages ship in a folder beside the program, and `add_character_packages_for` copies into a project's `assets/characters/` only what the given descriptions name (files already there are kept); `add_character_packages` copies all of it (Character Studio's own folder). `game_character.rs` is the default game character (refinement R10): the human base, `axcenity/human`, in a project (`add_default_game_character`, `add_game_character_library`, the shipped packages found by `shipped_character_library`) and the `Character` prefab described on it wearing `DEFAULT_GAME_OUTFIT` (`described_character`). `default_humanoid.rs` embeds the default humanoid's model and starter animations from `assets/characters/human/`; `add_default_humanoid` writes them and no library. `watch.rs` is the file watcher (`Watcher`, `Watched`): `notify` events trigger the stat-diff look, polling where events fail (live reload, `docs/editor/scripts.md`).
- Keep serialization deterministic and report damaged files through the existing `Project::problems`/error paths. Bump `FORMAT_VERSION` only with a migration plan.
- When core properties or enums change, update both project parsing and writing, and keep the example-project tests passing.
