# Known limitations

What the engine doesn't do, or does with a known flaw, today. Each entry names where it's documented. Performance issues are in [Known bottlenecks](../Performance/Known-Bottlenecks.md); structural problems in [Technical debt](Technical-Debt.md).

## Scripting

- No per-script **memory limit**; long C functions (`string.rep`, pathological patterns) aren't interrupted by the watchdog (`docs/scripting/sandbox.md`).
- `task.defer` runs at the next step (Roblox: later in the same frame); a RemoteEvent message with no handler is dropped (Roblox queues it); `ContextActionResult.Pass` and touch buttons not implemented (`docs/scripting/client-server.md`).
- Vector3 math allocates a userdata per result; `--!native` doesn't speed up engine calls.
- A breakpoint inside a C-called Lua function (a `table.sort` comparator), or in a script-made coroutine resumed from one, can't pause; a step goes on to the next line where it can. The same goes for a conditional breakpoint, a logpoint and Pause (Pause waits for the next script line that can pause, so a game whose scripts are all waiting pauses only when one wakes). Logpoints and conditions make their line yield on every pass, which slows a hot loop.

## Rendering

- Overlapping see-through items can blend in the wrong order (sorted by center).
- AMD/Vulkan/Windows: the sky clear isn't sRGB-encoded through an sRGB view (`docs/rendering/pipeline.md`).
- Lights are tiled in 2D, not clustered; rect lights use a representative point.
- No vertex colors or `KHR_materials_emissive_strength` from glTF; FBX uses the first UV set; glTF animations are read as bone takes, but their morph target weight channels aren't.
- Humanoid retargeting finds roles by bone names or by a rig definition of the project's (`assets/rigs/*.rig.json`); a retargeted take moves role bones only, so a bone without a role keeps its place (`docs/rendering/animation.md`).

## Physics

- MeshParts collide as convex hulls (hollows filled) unless already convex and small, their model has `_COL` collision pieces, or they're set to `PreciseConvexDecomposition` (R15.2). The Model Studio's Convex Pieces (R15.2b) runs on the UI thread and can take a few seconds on a big model.
- Setting `Position` stops a part (Roblox keeps its speed).
- Ragdolls can exceed joint limits briefly on hard landings.

## Networking

- **Game connections trust a typed address on first use** (MP4; a join link pins the fingerprint); a bare join code trusts the relay. Port mapping (MP5b) can't get past a provider's router (carrier-grade NAT; a relay can), and a killed host leaves its mapping until the 30-minute lease ends.
- No matchmaking or public relay (anyone can run `axcenity-relay`, MP5a), and prediction covers only characters (MP6a, under `Players.CharacterAuthority = "Server"`; physics bodies are MP6b; lag compensation and replays exist, Phase 81). Multiplayer has been measured with 16 bots across emulated home routers and 32 on one machine; a 16–32 client run on real machines (G13, MP7) is planned. All of it is planned in `docs/research/multiplayer-readiness.md` (MP1–MP7).
- **Server-moved characters** (MP6a): other players are drawn in the past on a device, so walking into a moving player costs a correction; moving platforms aren't rewound; seats, `MoveTo` and `MoveDirection` don't drive a remote player's character, and a device Script's `Jump` can be lost in a replay.
- Editor Play can't host or join a real network game.

## Characters

The Character Runtime (Character Studio overhaul CO3; [Characters](../Engine-Systems/Characters.md#applying-a-description-character-runtime), `docs/development/character-studio/architecture.md`):

- **Character Studio's interface is CO12's first part.** The workspace edits format 2 descriptions on any body of the library (the realistic one by default), previews them through the applier, and draws its Body, Face, Hair and Clothing pages from the manifest and catalogue (`docs/editor/character-studio.md`). Not yet: skin and makeup, accessories and expressions pages, colour and material pickers, a wardrobe browser with thumbnails and search, outfit presets, numeric entry, turntable and preview clips, clicking the body to open its category, and the round trip with the Game Editor (the rest of CO12). The realistic body has no clothes or hair to wear yet beyond its underwear (boxer briefs, briefs, a sports bra, cut from the body itself), (CO10, CO11). The stylized body is no longer offered for new characters; its saved characters still open. An installed editor offers it only when its payload has `assets/characters/` (`packaging/stage.py` stages it from this change on). A pack added to a project puts its characters in `assets/characters/descriptions/`, but a game script can't yet load a description by path: it sets a `HumanoidDescription`'s `Data` to the file's text.
- **The editor's edit mode doesn't apply kept descriptions.** `DescriptionSync` is stepped by the game systems, which run in Play, the player and the server. A saved character that had a description applied therefore shows its base meshes in the editor (its derived `MeshId`s fall back to the base model) until Play (CO13).
- **A project made before CO3 has no character library until Insert > Character is used.** The library is written with the default character (`project::add_default_humanoid`: a new project with a character, Insert > Character, Character Studio's workspace folder). An older project gets it the next time Insert > Character is used; until then `Humanoid:ApplyDescription` fails with a message that says the project has no character library, and a packed game built from such a project has none.
- **Some material values aren't drawn yet, and skin tone is one ratio per material.** Eye, cloth and hair materials draw as Standard; skin has its own shading model since R5 (`docs/rendering/skin.md`), which draws `scatter_scale`, `definition` and `softness` too. Drawn since 2026-11-17 (CO7's first slice): `tint`, `iris_tint`, `sclera_tint`, `roughness_scale`, `detail_strength` (the normal map's strength) and the pigments `melanin`, `undertone` and `redness`, which tone the whole albedo by one colour ratio from the references' indicative tone table (`crates/scene/src/skin_tone.rs`). So lips, nails, palms and soles tone with the rest (a deep tone darkens the lips with the skin; per-texel masks wait for the Skin shading model), the table's light end leans lavender-pink and is not yet recomputed from the pigment spectra, and colour values are drawn by name whatever the slot, so Hair's `melanin` and `redness` take the skin's curve. Not drawn: `pupil_size`, `limbal_ring` and `iris_depth` (the Eye model; the pupil has the `Pupil_Size` shape meanwhile), cloth sheen and anisotropy, hair dye, tip lightening and highlight.
- **Realistic skin: shading limits** (2026-11-17, R5; `docs/development/character-studio/refinement/r5/`). Fixed: the grain and the stippled terminator (the Skin shading model reads the normal map blurred for diffuse light, and the grain's cells are now 5 texels and half as steep), under TAA and MSAA alike; heavy bodies no longer show abdominal lines (a smooth and a defined normal map, blended by muscle and fat). Left: there is no screen-space subsurface blur or transmission, so light doesn't bleed past shadow-casting geometry (ears and nostrils lit from behind stay opaque); the curvature that sets how far red spreads comes from screen-space derivatives, constant per triangle; close up (the skin-close view) the grain's cells show faintly as a polygonal network in the forehead's highlight; the smooth normal map flattens the soft tissue's forms by 90% everywhere fat covers it, not by region. Without TAA (High and Ultra default to MSAA 4×, and Character Studio's viewport uses the editor's graphics settings) contact shadows keep their fixed pattern, so a limb in front of the body from the camera's view (not between the body and the sun) still casts a false screen-space contact shadow (it passes contact shadows' 0.5-stud thickness test); a fix is a thinner thickness for characters, or testing the blocker's depth gap against the march distance. The chest's dark band under the studio light (OPEN-09) is the light grazing the upper chest: the shadow terminator problem of a coarse mesh with smooth normals; not fixed.
- **Binding-fitted and socket items have no shipped content** (CO9, CO10): every item in the built-in library fits by its own copies of the body's shapes. A `binding` item would be drawn as a plain skinned part, unfitted.
- **A character's parts pick their levels of detail one by one.** A small part (underwear, eyes, brows) switches to a simpler copy nearer the camera than the body does, and a simplified garment doesn't keep its clearance from the skin: from about 9 studs the stylized character's skin shows through its underwear in blotches (seen in CO2's in-engine captures, which record each part's level in `captures.json`). Fixing it is CO18's "character LOD sets switched together", with CO9's region hiding (the body under a garment isn't drawn) and CO4's constrained LODs; until then judge clothing fit in the captures' full-detail view and in the Blender harness.
- **The identity bake's cost isn't measured** (CO18). A derived model is baked again in every run and whenever its base model is reloaded, never cooked, and each distinct description makes its own.

The realistic base body (Character Studio overhaul CO4, built and waiting for review; [Characters](../Engine-Systems/Characters.md#the-realistic-base-body), `docs/development/character-studio/testing.md`). Numbers are **Measured** with the Blender QA harness (`measure.py --package realistic`; masculine / feminine frame) and kept in `docs/development/character-studio/co4/measurements.json`:

- **`axcenity/realistic` is not yet a full character family.** It has its body shapes (CO5), its head and face (CO6) and underwear, but no hair or other clothes, and the library written into a project is still the stylized package alone.
- **The realistic underwear is an interim fit** (2026-11-16): copied body shapes (37 to 53 per garment) and mask shapes that sink the skin under it 5 mm, an exception to [ADR-0035](../Architecture/Architecture-Decisions/ADR-0035-Clothing-Fits-By-Surface-Binding-With-Region-Hiding.md) until CO9's region hiding; the briefs' back hem meets the gusset in a small crumple seen from below.
- **The realistic face is short of a photograph** (CO6, judged in 4K engine captures against reference photographs): no creases anywhere (no wrinkle maps); the eye's shade is a film between the lids that does not know where the light is, so the whites are lit alike in every light (eye shading is CO7); a closed lid under side light shows the head's own shadow edge as a lit blotch; a closed smile is milder than a real one; an open mouth's corners are points and its lower back teeth can be made out close up; the jaw fully open is bell-shaped; the U and WQ visemes show the front teeth; lashes and brows are cards; the pupil has no slider; some face parameters at their ends still cross the head's own triangles (the masculine `eye_size` -1 shows as a lit streak on the upper lid). The package's sliders check is red on one line from three false counts in its eye measure, which signs a point by one face where two tie at an edge; the measure is unchanged until the project owner decides. Details: `docs/development/character-studio/co6/README.md`.
- **The raised shoulder keeps less local volume than once targeted (decided, 2026-11-16).** With the arm raised 150 degrees and CO5's corrective shapes the shoulder keeps 0.463 / 0.513 of its local volume (the old target was 0.8; plain skinning gave 0.562 / 0.561). The local volume rewards an inflated cap (a shape that passed it showed a step and a ball in the engine), so the project owner decided the 150 degree shoulder is held by its ring area instead: 0.929 / 0.82, with a floor of 0.92 / 0.81 in the package's thresholds; the local volume is still measured and reported. A collarbone that lifts with the arm, as a real one does, would raise both and is left for the second wave. The arm lowered to hang, as the starter clips hold it, has its own corrective shapes since 2026-11-16: before them the cap squared off and a ridge rose beside the neck (the shoulder gained 12.5 / 9.3% of its local volume); with them it keeps within 2.4% of rest. At 90 degrees the shoulder keeps 0.847 / 0.88 against targets of 0.853 / 0.992 (the stylized body's), printed as not met. The other CO4 targets are met: the elbow at 135 degrees keeps 0.757 / 0.758 and the knee 0.74 / 0.75 of the ring area (0.6 or more), no face vertex above the head joint carries `Neck` weight (the stylized body has 911), and eyes and teeth don't interpenetrate at rest or at any face parameter's end (`docs/development/character-studio/stage3/`).
- **Still short elsewhere on that body:** the fist self-intersects (247 / 199 triangle pairs). The teeth touching the lower lip with the jaw open and the lips resting 2 mm apart were fixed in CO6.
- **The realistic body's sliders stop short.** Its proportion sliders run 0.85 to 1.15 and its hips only widen, because the body crosses itself beyond (**Measured**: 341 of 1,404 masculine bodies at the full 0.5 to 1.5). corrective shapes exist for the arm raised sideways only; the corrective rules are constants in `crates/anim/src/correctives.rs`, with no manifest field yet.
- **Twist and helper bones are found by name.** No manifest field describes the driver rule yet, so only a skeleton that uses the names in `crates/anim/src/twist.rs` is driven ([Animation](../Engine-Systems/Animation.md)).

## Editor

- Script completion and Go to Definition (F12) follow chains and declarations but doesn't type-check: a value it can't follow (a function's result, a table field, a module's return) offers nothing, luau-lsp ships in every package (a source build downloads it on request) and follows `require(game.ReplicatedStorage.X)` and `GetService` paths into modules (not `require(script.Parent.X)`, nor children's types such as `workspace.Door`); only open tabs are checked, and VS Code's set-up still checks each file alone.
- Panics while drawing the Play world aren't caught.
- **Group as Mesh** carries what a glTF material can hold. A Part's built-in Material texture (Wood, Brick, Concrete…, drawn from maps `scene` makes in memory) is grouped in its color; MaterialVariants, a Part's SurfaceAppearance, opacity and specular maps, DirectX normal maps and Decals aren't carried either (Output names each part). Hidden faces are only taken away when one solid part, or opposite faces in one plane, cover them; a face hidden by two overlapping parts together stays. Faces only partly pressed together stay whole (`docs/architecture/solid-modeling.md`).
- Model files aren't watched for changes while the editor runs (read again on open).
- Bakes (reflection probes, light probe volumes) go stale and must be rebaked by hand (flagged). A bake runs a little each frame with progress and Cancel, but each probe still reads its six faces back one at a time, so thousands of probes take minutes.

- **A SurfaceAppearance's normal map on a model whose own material has none is drawn without tangents** (every corner's tangent is `render::mesh::NO_TANGENT`, +X in the model), because `assets` works tangents out only for a material with a normal map of its own. Found by Group as Mesh's picture test on hello-mesh's ATM: the grouped model's material links the map itself, gets real tangents, and its bumps light differently (more correctly) than the separate MeshPart's.

## Content and platforms

- References may name an asset by path or by ID (PR #78); older projects still use paths.
- Built games ship cooked textures without their sources (G12); what the CPU reads of such a texture (terrain layers, color grading lookups, UI images) is decoded from BC7 or BC5, so it's close to the source, not equal. Model files (FBX, glTF) still ship beside their cooked copies.
- macOS is not verified on changes; mobile and web are not supported.
- No binary world format (S10k's 10 MB `world.json` loads in 0.19 s since C11).
